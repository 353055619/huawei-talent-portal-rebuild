# 华为高校人才 IT 系统重构 · 调研总报告

> 调研时间：2026-11-15 ｜ 方法：现网一手体验（未登录+登录态逐模块遍历）+ 4 份并行业界调研（国内大厂/海外平台/GitHub 开源/华为生态业务背景）
> 配套材料：`00-现网系统信息架构笔记.md`（一手遍历记录）、`01~04` 调研分报告

---

## 一、执行摘要

1. **现网最大的问题不是功能缺失，而是"一个业务、七套系统"**。学校入驻在 partner.huawei.com、课程学习器在 outPage/sxz、考试在 shixizhi.huawei.com、问卷在 survey.huaweicloud.com、考券在 usercenter、企业证书绑定在 myspace、笔试又在 Pearson VUE。同一个用户旅程被切成 7+ 段，登录态与上下文反复中断。
2. **能力上有结构性缺口**：就业/双选会（生态的核心卖点）没有任何线上产品；院校管理员和教师没有工作台（教师"开班"埋在课程详情页的一个按钮里）；数据洞察（培养量/认证率/就业去向）完全缺位。
3. **体验上有大量硬伤**：用户中心子页面丢失左侧菜单、未登录点"报名"零反馈、考券申请路由是空白页、实名认证只改 URL 不改内容、"我的课程"提示平台升级导致学习记录断档、账号姓名字段被填成账号 ID。
4. **业界标杆给出的方向是一致的**：以"高校四端"（学生/教师/院校管理员/厂商运营）为中心的一体化平台 + 全旅程进度透明 + 可信身份（学校 SSO/学信网式认证）+ 数据闭环（outcomes）。Handshake 做学生-高校-雇主三方市场，Symplicity/12twenty 做高校就业办公室工作台，Greenhouse/Ashby 做结构化与自助排期，思科 NetAcad 做"免费 LMS+认证变现"——华为生态的业务复杂度高于所有这些对标，但平台化程度显著更低。
5. **重构建议一句话**：把"营销门户 + N 个交易系统"重组为"一个账号、一个工作台、四个角色端、九大业务域"的一体化高校人才平台，就业对接做成线上闭环，数据洞察作为一等公民。

## 二、现网系统全景

### 2.1 系统地图（实测确认）

```
华为账号 uniportal.huawei.com（唯一登录入口，好消息）
└─ e.huawei.com/cn/talent/* 「华为人才在线」微前端（≈10 个子应用）
   ├─ portal 首页（营销）        ├─ learning 课程目录
   ├─ cert 认证介绍              ├─ ict-academy 学院/大赛/课程详情
   ├─ usercenter 个人中心        ├─ halp 培训伙伴
   ├─ success-stories/news       ├─ outPage/sxz-course 学习器（iframe）
   └─ backplatform 文件下载
├─ elearning.huawei.com    商城/华为认证官网（另一套系统）
├─ partner.huawei.com      学校入驻（eplusweb+metaEcpri）
├─ talent.shixizhi.huawei.com  考试（iexam）
├─ survey.huaweicloud.com  问卷    ├─ edu.huaweicloud.com 活动报名
├─ e.huawei.com/cn/myspace 企业证书绑定
└─ Pearson VUE             认证笔试
```

### 2.2 核心用户旅程实测（问题标注 ⚠️）

**旅程 A：学校入驻（院系管理员）**
ICT学院首页"立即注册"→ 跳 partner.huawei.com ⚠️（跨系统）→ 下载《授权函》盖二级学院公章 ⚠️（纯线下）→ metaEcpri 填表上传扫描件 → 邮件等审批 ⚠️（无站内进度）→ 在线签校企合作协议 → 认证分级（认证/优选/领先）→ 通过后再回人才在线管理 ⚠️（管理入口在"用户中心"，与入驻系统分离）。

**旅程 B：教师开班**
登录 → 个人信息 → 点"关联-讲师"自填身份 ⚠️（无学校可信认证，靠审批）→ 课程详情页找"我是老师-我要开班" ⚠️（开班入口藏在课程页而非教师工作台）→ 生成邀请码 → 线下发给学生 → 学生凭邀请码进班 ⚠️（无"本校班级"自动关联）。

**旅程 C：学生学习**
首页/学习频道选课 ⚠️（133 门课，未登录点"报名"零反馈）→ 课程详情 → "去学习"新开标签到 sxz 学习器 ⚠️（第 3 次跳转）→ 学习 → 结课测试；"我的课程"提示"平台升级建议重新学习" ⚠️（记录断档）。

**旅程 D：学生认证考试**
认证频道了解 → 实名认证 ⚠️（点了只改 URL）→ 考券：学校/IASC 发放 → 我的券包（暗码/数字考券，占用后 24h 自动取消等复杂规则）⚠️（考券申请页面空白）→ 预约考试跳 Pearson VUE ⚠️（外部）→ 证书在 talent/#/personal/mycert 下载 → HCIE 纸质套件 15-30 工作日邮寄。

**旅程 E：学生参赛**
ICT大赛频道 → 选赛道/赛区 → 报名（中国区已截止时只显示"报名已结束"）→ 省资格赛在 shixizhi 考试系统 ⚠️（外域）→ 认证优惠活动报名在 edu.huaweicloud.com ⚠️。

**旅程 F：就业（断头路）**
全站宣传"每年数十场双选会、1000+ 合作企业、近千岗位"，但**没有任何双选会/岗位/投递功能的入口** ⚠️⚠️——生态价值链的"最后一公里"在线上是断的。

## 三、业务能力缺陷清单（对标 9 大业务域）

| 业务域 | 现网状态 | 缺陷 |
|---|---|---|
| 1 合作签约与院校档案 | partner 系统 + 线下盖章 + 邮件审批 | 无站内全流程追踪；分级评审无看板；入驻后管理跳回另一系统 |
| 2 课程与教学 | learning 目录 + sxz 学习器 + 邀请码班级 | 三处拼装；升级断档；教师无工作台；无成绩/学分回传 |
| 3 师资 | "关联-讲师"自助申请 | 无讲师档案/认证路径可视化（HCAI/TTT 流程不在线上）；赋能活动无排期系统 |
| 4 认证与考试 | 券包+VUE+myspace | 考券申请空白页；状态机复杂但无引导；跨 4 系统 |
| 5 竞赛 | 大赛频道+shixizhi 考试 | 报名/考试分离；资料靠 PDF；无参赛进度/团队管理线上化 |
| 6 实习就业 | **无** | 双选会/岗位/简历/投递全缺——最大空白 |
| 7 产学研项目 | 散在 huaweicloud 各活动页 | 众智/火花等无统一立项-结题管理 |
| 8 资源与内容 | 下载专区+GitCode 外链 | 可用但分散；无版本/检索体验一般 |
| 9 数据洞察与运营 | **无（面向院校/教师）** | 院校看不到自己学院的学生学习/认证/参赛/就业数据；IASC 无运营工具 |

**横向体验缺陷（不分域）**：子页面丢失左侧菜单；空状态无引导；新标签页泛滥（一次会话 7+ tab）；中英文/多语言在子站间不一致；HALP 公告停在 2023（运营断更信号）；账号资料质量差（姓名=账号ID）且"确定后无法修改"。

### 4.2 最值得抄的 12 条实践（来源标注）

1. **学校 SSO/可信学生认证**（Handshake/Symplicity）——身份即信任，这是双选会雇主敢来的前提；国内可用学信网式校验
2. **院校工作台而非入口**（Symplicity/12twenty）——预约排期、学生 CRM、文档审核、自定义仪表盘
3. **就业去向 outcomes 数据闭环**（12twenty/Handshake）——投递→offer→去向全链路，产出法定报告与排名依据
4. **雇主资质审核机制**（Handshake 的教训）——防虚假岗位是学生信任生死线，审核要产品化且持续运营
5. **申请状态看板+时限承诺**（Google Dashboard/Microsoft 90天）——所有申请集中可查，宁可慢不可沉默
6. **自助排期**（Greenhouse，排期工时 243→27 分钟）——宣讲/面试/双选会时段自选
7. **OCR/bid 式双选会数字化**（Symplicity）——展位地图+预选+签到+会后数据
8. **银牌人才池 Nurture**（Lever/Handshake 校友库）——今年不合适明年自动再触达；对应"大一蓄水→认证→大赛→就业"漏斗
9. **免费学习+认证变现**（思科 NetAcad：3330万学习者）——个人免费自助学习，考试折扣券导向认证收入
10. **AI 招聘 Agent + 按简历定制的 AI 面试练习**（美团/牛客）——7×24 答疑与备考
11. **游戏化校招旅程**（RippleHire）——积分/徽章/即时反馈适配 Gen Z
12. **AI 评测合规红线**（HireVue 教训）——可解释、可选、不采集生物特征

## 五、重构建议

### 5.1 北极星与设计原则

**北极星**：让一所高校从"签约共建"到"学生就业去向"的全旅程发生在一个平台内，四端角色各有一个工作台，每一步进度可见。

原则：
1. **一个账号走天下**（uniportal 保留）+ 站内路由替代新开标签（技术债清零）
2. **身份分层**：华为账号 → 实名 → 校籍（学校 SSO/学信网式校验）→ 角色（学生/教师/院管/IASC/HALP/雇主），角色可叠加、可审批、可追溯
3. **一切状态皆可追踪**：入驻审批、关联审批、考券、报名、竞赛晋级、投递进度全部有站内进度条 + 消息中心（消灭"邮件等通知"）
4. **空态即入口**：每个空列表都有"去报名/去认证/去开班"的 CTA
5. **数据洞察一等公民**：院管/教师/IASC/华为运营四级看板

### 5.2 目标信息架构（四端一后台）

```
┌─ 学生端：首页(个性化) 学习(课程/实验/班课) 认证(约考/券/证书) 竞赛 成长档案 就业中心(岗位/双选会/内推) 消息
├─ 教师端：工作台(我的班级/学生/进度) 开班开课 教学资源 讲师认证 赋能活动 奖教金
├─ 院校管理端：工作台(学院数据看板) 学院档案与分级评审 教师学生管理 考券配额 双选会协办 就业去向报告
├─ 生态端（IASC/HALP/雇主）：运营工作台 渠道管理 活动管理 岗位发布与审核 人才检索
└─ 平台后台：内容/课程/竞赛配置 审批流 权限 数据洞察 运营配置
```

### 5.3 能力蓝图（三阶段）

**P0 修硬伤（重构必达）**
- 统一壳与导航：消灭新标签跳转、子页面左侧菜单常驻、面包屑可回退
- 未登录行为规范：报名/开班等动作引导登录并带回跳
- 修空白路由（考券申请）、实名认证渲染、资料字段质量
- 全站消息中心 + 待办聚合（现在"待办事项" tab 已存在但为空壳）

**P1 补闭环（6-12 个月）**
- 院校入驻全流程线上化：授权函电子签/OCR、站内审批流与进度、入驻后管理同域
- 教师工作台 + 班级组织模型升级：学院-班级-学生自动关联（替代纯邀请码），成绩册、学习进度批改
- 就业中心 MVP：双选会活动管理（报名/展位/签到）、岗位发布与审核、学生成长档案（课程+认证+竞赛画像）生成可投递简历
- 竞赛一体化：报名-组队-资格审核-考试(shixizhi 内嵌)-晋级看板
- 院校数据看板 v1：学生学习量/认证通过率/参赛/就业去向

**P2 做深度（12-24 个月）**
- 学校 SSO/学信网式校籍认证；可被雇主发现的学生档案（授权制）
- AI：岗位/课程推荐、AI 备考助手（按课程/认证定制）、简历助手；严守可解释/可选红线
- 雇主生态：资质审核、人才检索、银牌池 Nurture、outcomes 报告（对接高校就业质量年报）
- 多语言/全球赛区的一致体验（现在 110 国但体验以中国区为先）

### 5.4 度量建议（重构验收标准）

- 旅程完整性：任一核心旅程跨系统跳转次数 = 0
- 学生"报名到开始学习"点击数 ≤ 3；"发现岗位到投递" ≤ 5
- 院管周报生成：自动（现状：人工无从统计）
- 空态 CTA 覆盖率 100%；所有审批类动作站内进度可见率 100%

## 六、风险与注意事项

1. **存量数据迁移**：现网已暴露"平台升级学习记录断档"，重构必须做数据迁移方案与用户补偿沟通
2. **多系统归属不同团队**：partner/shixizhi/elearning 分属不同 BU，重构范围与治理机制需先对齐（建议平台化 + 明确 API 契约，而非物理大单体）
3. **合规**：学生个人信息（未成年人可能有）、跨境（110 国）、AI 评测红线、数据出境
4. **许可证**：借鉴开源时的 GPL/AGPL 传染性评估
5. **运营带宽**：HALP 公告断更说明"建系统"之外还要"养系统"，重构需配套运营指标
